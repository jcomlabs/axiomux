# Known issues

Reference state: `Axiomux 0.1.0-alpha`, 2026-07-18. The implementation was developed under the internal name `SUPERAI`; `.superai`, `SUPERAI_*`, and some code identifiers remain compatibility namespaces. This list distinguishes Axiomux defects, risks inherited from dependencies, and validation gaps. “Mitigated” does not mean “eliminated.”

## Open risks

| ID | Priority | Status | Issue | Current mitigation |
|---|---:|---|---|---|
| KI-001 | high | open upstream | In OMP `17.0.2`, some OAuth callback servers advertised as `localhost` were observed binding to `0.0.0.0`. The reviewed `17.0.4` monitored diff did not change those flows, so OpenAI Codex, Anthropic, and GitLab remain conservatively treated as affected. Another device on the network may reach the port during the login window. | The CLI displays a prominent warning and requires confirmation before these logins. Use a trusted network with no port forwarding; prefer `openai-codex-device` for OpenAI. There is no complete local fix. |
| KI-002 | high | accepted in alpha | There is no operating-system sandbox for approved host executables or adapters. `shell: false`, allowlists, governed paths, and approvals reduce risk, but the process still runs with the user's privileges. | Use the minimum profile, review each action, and use a disposable VM/account for Browser Use and UFO. |
| KI-003 | high | accepted in alpha | Conversations, memory, sources, workflows, audit data, and OMP databases are stored as local plaintext. ACLs/`0700` protect the boundary between user accounts, not against malware running as the same user. | Protect `.superai/`, backups, and exports. Only the persisted Neuralwatt key uses DPAPI `CurrentUser`. |
| KI-004 | high | partially mitigated | The 57 authentication flows exposed by OMP have not been tested with 57 accounts. OpenAI Codex is now proven in the isolated vault with 19 models, a GPT-5.6 turn, online doctor probe, and governed host-tool E2E; this says nothing about the other flows. | Maintain a per-provider matrix covering catalogue discovery, login, model discovery, a real turn, date, and OMP version. | KI-016 | medium | technical debt | The runtime uses the SQLite API that is still marked experimental in Node 24. Migrations and restore/upgrade workflows are not product-mature. | Use backups and an alpha version label; add migration tests before 1.0 stability. |

## Pinned runtime facts

- OMP contract: `omp/17.0.4`, tag/commit `3fdd85ab6c6bab6c0cdee80abbbec0981740a5c0`.
- `npm run omp:install` confirmed the project-managed runtime `.superai/bin/v17.0.4-omp-windows-x64.exe` on this machine with the correct version and digest.
- The runtime contains the official per-platform SHA-256 manifest published with release `v17.0.4` and verifies the executable before every spawn. Supported platforms: `darwin-arm64`, `darwin-x64`, `linux-arm64`, `linux-x64`, and `win32-x64`.
- Observation on this machine: SHA-256 `326FB7DF19A8A4516F129A52D60373B547F732C17F19D4C38700F3591D85AA73`, equal to the official `win32-x64` digest; Authenticode status `NotSigned`.
- Observed catalogue: 57 OMP flows plus native Neuralwatt, for a total of 58 authentication/configuration providers. “Provider” in this count does not guarantee a chat backend or available models.

## Closed items

- The former executable Neuralwatt bridge was removed. The note that `--no-extensions` also blocked that bridge is now obsolete.
- Neuralwatt is now native Axiomux code, with a secret-free catalogue and a DPAPI/environment key provided only to the Neuralwatt child process.
- Strict OMP processes use `PI_AUTH_NO_BORROW=1`, preventing silent credential import from desktop applications supported by OMP.
- RPC remains the normal login path. Only known pre-auth failures fall back to the official `auth-broker` CLI subcommand in the same isolated vault.
- **KI-011 closed:** multi-project passed an E2E test with two workspaces: separate roots/current directories, one central vault, isolated project/global sessions and memory, blocked host escape, explicit global search, and per-project CLI/UI routing.
- `shared` and `yolo` were removed and are rejected by the validator: the former reopened implicit global authority; the latter removed human approval and effect safety.
- Fallback exposes `status|set|clear`, starts empty, and allows at most 8 routes; Fusion/MoA and UI Routing use the unified catalogue with up to 8 participants and native Neuralwatt.
- The `upstream list|check|show|mark` radar is metadata-only Git inspection with a baseline and human review; it downloads no blobs, patches, or repositories and never auto-applies changes.
- `yaml 2.9.0` and `ipaddr.js 2.4.0` are pinned and permissively licensed.
- The frozen Python audit reported no known vulnerabilities after explicit overrides for `aiohttp`, `click`, `mcp`, `pillow`, and `pypdf`.
